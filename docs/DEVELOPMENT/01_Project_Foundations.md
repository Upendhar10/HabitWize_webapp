# Project Foundations

This phase establishes the foundational structure of the project before implementing any project-specific functionality.

The goal is to set up the development environment, project workspaces, tooling, and core configurations required to build and maintain a modern full-stack application.

This phase includes:

- Setting up the frontend and backend workspaces.
- Configuring root-level workspace management.
- Establishing Git and development tooling.
- Setting up the initial frontend and backend foundations.

---

## 1. Frontend Project Foundations

### 1.1 `chore(frontend): initialize React app using Vite`

**What I did**

- Bootstrapped the React application using Vite.
- Chose TypeScript as the primary language for the frontend.
- Removed the default boilerplate code generated by Vite.

**Why**

- Chose Vite for its fast development server, modern build tooling, and streamlined React setup.
- Chose TypeScript to improve type safety, code maintainability, and developer experience as the application grows.

---

### 1.2 `chore(frontend): configure ESLint and Prettier`

**What I did**

- Integrated **`eslint-config-prettier`** with the existing ESLint configuration to prevent conflicts between ESLint and Prettier rules.

- Installed **`prettier`** as a development dependency and configured formatting rules for consistent code style.

**Why**

- **`ESLint`** helps identify potential code issues, invalid syntax, unused values, and other common problems early during development.

- **`Prettier`** ensures consistent code formatting by enforcing standardized rules for aspects such as semicolons, indentation, spacing, and line breaks.

- Separating linting and formatting responsibilities keeps the codebase consistent, readable, and easier to maintain.

---

### 1.3 `chore(frontend): configure TypeScript settings`

**What I did**

- Added **`"moduleResolution": "NodeNext"`** to **`tsconfig.node.json`** to align module resolution with the existing **`NodeNext`** module configuration.

- Removed **`"erasableSyntaxOnly": true`** from **`tsconfig.node.json`**.

- Enabled **`"strict": true`** in **`tsconfig.app.json`** to enforce stricter type-checking across the application.

**Why**

- Configured **`"moduleResolution": "NodeNext"`** to ensure TypeScript resolves modules consistently with the project's **`NodeNext`** module system.

- Removed **`"erasableSyntaxOnly": true`** to avoid restricting the TypeScript syntax supported by the project.

- Enabled **`"strict": true`** to improve type safety and catch potential type-related issues earlier during development.

---

### 1.4 `chore(frontend): configure Tailwind CSS v4 as a Vite plugin`

**What I did**

- Installed **`tailwindcss`** and **`@tailwindcss/vite`** as project dependencies.

- Configured the Tailwind CSS Vite plugin in the application's **`vite.config.ts`** file.

- Installed **`prettier-plugin-tailwindcss`** as a development dependency to automatically sort Tailwind CSS utility classes during formatting.

**Why**

- Chose **Tailwind CSS** as the primary styling solution because of its utility-first approach, flexibility, and seamless integration with modern React applications.

- Configured Tailwind CSS as a Vite plugin to take advantage of the recommended Tailwind CSS v4 integration and simplify the project's styling setup.

- Added **`prettier-plugin-tailwindcss`** to automatically maintain a consistent and predictable ordering of Tailwind CSS classes, improving code readability and maintainability.

---

### 1.5 `chore(frontend): configure TypeScript and Vite path aliases (@)`

**What I did**

- Upgraded `@types/node` to version `26.1.1` to support the required Node.js type definitions.

- Defined the `@` path alias in `tsconfig.app.json` to simplify imports within the application.

- Updated the import syntax in `main.tsx` to use the `@` alias instead of relative paths.

**Why**

- Configured path aliases to provide cleaner and more readable import statements.

- Using the `@` alias makes imports easier to maintain as the project grows and the folder structure becomes more complex.

- Keeping the alias configuration in TypeScript and Vite ensures that the `@` syntax is consistently recognized during development, type-checking, and builds.
